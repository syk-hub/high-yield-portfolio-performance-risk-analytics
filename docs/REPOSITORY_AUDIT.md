## Findings

1. **Original synthetic generator and outputs.** `portfolio_analytics.py`
   defines ten inline synthetic `USM-*` bonds in
   `build_simulated_bonds()`. It constructs portfolio and equal-weight
   benchmark frames, then writes legacy holdings CSVs, a data dictionary,
   summary JSON, charts, HTML, and a manager note. These are under `data/`
   and singular `output/`, separate from the current documented-bond inputs
   and plural `outputs/`.

2. **Code tied to the original dataset.** The test module imports the legacy
   script. Both SQL files use its `bond_id`, `holdings_snapshot`, and
   `benchmark_weights` model. The files under legacy `data/` and `output/`
   contain the synthetic USM dataset or its results.

3. **SQL and configuration to adapt.** The schema's provenance and exception
   concepts, as well as duplicate, null, dirty-value reconciliation, and
   price-movement checks, are useful patterns. They are not currently wired
   to current Python calculations or CSVs, and should be revised before
   use. `requirements.txt` supports the legacy plotting/dataframe script.
   `.gitignore` remains useful configuration.

4. **Documentation with obsolete workflow instructions.** The root README's
   execution command and file layout point to the original workflow.
   `PROJECT_SPEC.md` remains useful, but its sequencing and deliverables
   should be reconciled with the current teaching workflow.

5. **Preservation status at audit time.** `git ls-files` listed only
   `.gitignore` and `PROJECT_SPEC.md` as tracked. `PROJECT_SPEC.md` was
   modified. The current inputs and scripts, `BOND_RESEARCH.md`, root README,
   `portfolio_analytics.py`, legacy `data/` and `output/`, SQL, tests, and
   current `outputs/` were untracked. Preserve these before any cleanup.
   In particular, `portfolio_analytics.py` remains referenced by both the
   README and tests, so it is not an unconditional removal candidate.
